# PHASE 0: PRE-PRODUCTION

## Purpose

Establish the scaffolding before filling in the details. This phase ensures consistency, completeness, and efficiency across the entire book production process.

---

## Step 0.1: Define the Book's Core Thesis

### Primary Thesis Statement

**MICOS-25 is a constitutional system for designing, evaluating, and governing large-scale institutional platforms. It provides a standardized framework that ensures any institutional project is Bankable, Scalable, Resilient, Transferable, and Politically Durable.**

### Secondary Thesis (The Book's Purpose)

This book is the **canonical commentary** on the MICOS-25 framework. It expands every section of the framework into a comprehensive narrative, answering all possible questions—Who, Whom, What, Where, When, Why, Which, Whose, How, and their compounds—to transform a lean institutional code into a complete pedagogical resource for students, practitioners, and AI systems.

### Tertiary Thesis (The Ultimate Goal)

The book aims to replace ad-hoc planning, personality-driven control, and informal governance with **institutional permanence**. It is a blueprint for building systems designed to last, thrive, and be replicated across generations.

## Step 0.4: Establish the Q\&A Question Bank

### Master Question List

This is the palette from which you will select questions for each statement type.

#### Core Questions (Apply Universally)

| Question | Purpose |
| :---- | :---- |
| **What is it?** | Establish definition and shared understanding. |
| **Why does this matter?** | Establish significance and rationale. |
| **How does it function?** | Explain mechanics and process. |
| **Who is responsible?** | Identify accountability and ownership. |

#### Definition-Focused (For Concepts, Components, Documents)

| Question | Purpose |
| :---- | :---- |
| **What does it include?** | Inventory elements and structure. |
| **What is its purpose?** | Clarify intention and function. |
| **What are its key characteristics?** | Describe defining features. |
| **How is it structured?** | Explain architecture and relationships. |
| **How is it created?** | Describe production or formation process. |
| **When is it used?** | Clarify timing and context. |
| **Where is it located?** | Identify physical or organizational position. |

#### Problem-Focused (For Failure Modes, Red Flags)

| Question | Purpose |
| :---- | :---- |
| **How does it become a failure mode?** | Explain mechanism of failure. |
| **What are the consequences?** | Describe impact and outcomes. |
| **What does it look like in practice?** | Provide concrete example. |
| **How is it detected?** | Describe diagnostic methodology. |
| **What are the warning signs?** | Identify early indicators. |
| **Why is it a red flag?** | Explain significance and risk. |
| **What is the potential impact?** | Describe consequences if unaddressed. |
| **How is it prevented?** | Describe mitigation strategies. |
| **How is it corrected?** | Describe remediation methods. |

#### Solution-Focused (For Design Principles, Patterns, Implementation Steps)

| Question | Purpose |
| :---- | :---- |
| **Why is this a principle?** | Explain rationale and significance. |
| **How is it implemented?** | Describe execution methodology. |
| **What are the trade-offs?** | Identify pros, cons, and balancing considerations. |
| **What happens if it is violated?** | Describe consequences of non-compliance. |
| **What are the prerequisites?** | Identify preconditions and dependencies. |
| **What are the common pitfalls?** | Describe typical mistakes and avoidance strategies. |
| **When is it appropriate?** | Clarify conditions and suitability. |
| **What problem does it address?** | Explain context and applicability. |

#### Evaluation-Focused (For Scorecards, Stress Tests, Bankability Tests)

| Question | Purpose |
| :---- | :---- |
| **What is the purpose of this tool?** | Clarify function and intention. |
| **How is it used?** | Describe application methodology. |
| **What does it reveal?** | Explain insights and analysis. |
| **How is it assessed?** | Describe evaluation criteria. |
| **What constitutes a passing result?** | Define success standards. |
| **What are the financial implications?** | Explain impact on cost of capital, valuation, etc. |

#### Relationship-Focused (For Dependencies, Connections)

| Question | Purpose |
| :---- | :---- |
| **What are the prerequisites?** | Identify upstream dependencies. |
| **What does it feed into?** | Identify downstream impact. |
| **How does it connect to other chapters?** | Explain lateral relationships. |
| **Why does this boundary matter?** | Explain significance of scope limits. |

#### Compound Questions (For Timing, Frequency, Extent)

| Question | Purpose |
| :---- | :---- |
| **How often is it updated?** | Establish frequency and review cycle. |
| **How long does it take?** | Estimate duration and timeline. |
| **How many are required?** | Quantify needs and quantities. |
| **How far does it extend?** | Define scope and reach. |

### Question Selection Rules

| Rule | Explanation |
| :---- | :---- |
| **Start with "What is it?"** | Every section must begin with a clear definition. |
| **Select questions based on statement type** | Use the mapping above to choose relevant questions. |
| **Limit to 3-5 questions per item** | Too many questions dilute the message. Focus on the most relevant. |
| **Follow logical progression** | Definition → Context → Mechanism → Impact → Mitigation → Responsibility. |
| **Be consistent within categories** | All Failure Modes should follow the same Q\&A pattern. |

## Step 0.5: Create the Style Guide

### Formatting Standards

| Element | Standard |
| :---- | :---- |
| **Headings** | `# H1`, `## H2`, `### H3`, `#### H4`, `##### H5` |
| **Bold** | `**Text**` for emphasis and key terms. |
| **Italics** | `*Text*` for technical terms on first use and case names. |
| **Code Blocks** | ```` ``` ```` for matrices, tables, and code. |
| **Blockquotes** | `>`  for extracted quotes or key insights. |
| **Lists** | Use `-`  for unordered lists, `1.`  for ordered lists. |
| **Links** | `[Text](URL)` for cross-references and external links. |
| **Tables** | Use markdown tables with \` |

### Capitalization Conventions

| Element | Standard |
| :---- | :---- |
| **Chapter Titles** | Title Case (e.g., "Chapter 3: Capital Structure") |
| **Section Headings** | Title Case (e.g., "Strategic Function") |
| **Subsection Headings** | Sentence case (e.g., "What is it?") |
| **Key Terms** | Bold on first use, then standard. |
| **Chapter References** | "Chapter X: \[Name\]" (e.g., "Chapter 3: Capital Structure") |
| **Framework References** | "MICOS-25" always with hyphen and numbers. |
| **Layer References** | "Layer 1: Structural Foundation" |

### Example Standards

| Element | Standard |
| :---- | :---- |
| **Example Introduction** | Use `**Example:**` in bold, followed by italicized company name. |
| **Company Names** | Italicized, descriptive names (e.g., *GreenTech Innovations*). |
| **Case Study Names** | Italicized, descriptive names (e.g., *The "Silent" MFN*). |
| **Example Structure** | Context → Problem → Consequence → Lesson Learned. |
| **Example Length** | 2-4 paragraphs for each example. |

### Cross-Reference Standards

| Element | Standard |
| :---- | :---- |
| **Chapter References** | `Chapter X: [Name]` (e.g., "See Chapter 2: Governance") |
| **Section References** | `Section X.Y: [Name]` (e.g., "See Section 3.4: Failure Modes") |
| **Footnote References** | Use markdown footnotes `[^1]` sparingly. |
| **Source References** | Use inline citations for quoted sources. |

### Language Standards

| Element | Standard |
| :---- | :---- |
| **Voice** | Active voice preferred over passive. |
| **Tense** | Present tense for definitions and principles. Past tense for examples and case studies. |
| **Pronouns** | Use "you" sparingly. Prefer "the institution," "the board," or "the architect." |
| **Clarity** | Define all technical terms on first use. |
| **Conciseness** | Avoid redundancy. One clear explanation beats multiple vague ones. |

### Document Structure

| Element | Standard |
| :---- | :---- |
| **Front Matter** | Title page, table of contents, list of figures, list of tables. |
| **Chapter Structure** | Consistent template for all 25 chapters. |
| **Layer Introductions** | Four layer introductions before their respective chapters. |
| **Appendices** | Case studies, glossary, index. |
| **Back Matter** | About the author, acknowledgments, version history. |
